# 메뉴 간소화 계획

작성일: 2026-09-11
상태: 구현 및 검증 완료. 사용자 승인에 따라 현재 작업 폴더에 반영했으며, 커밋·배포는 하지 않음. 검증 기록은 `navigation-qa.md` 참조.

## 목표

현재 8개 메뉴를 **브리핑 / 탐색 / 법령·규제 / 작업실** 4개로 줄인다.
기능을 없애기보다 사용 목적에 맞게 합치고, 같은 요약·기사·과제를 여러 화면에 반복해서 싣지 않는다.

## 현재 중복과 통합안

| 현재 | 변경 | 역할 |
| --- | --- | --- |
| 홈 + 이번 주 + 리뷰 | 브리핑 | 이번 기간에 무엇이 중요하고 무엇이 달라졌는지 파악 |
| 분석 + 연관어 + 이슈 추적 | 탐색 | 관심 주제를 검색하고 근거·연관성·시간 흐름 조사 |
| 법령·규제 | 유지 | 제도 변경과 시행일, 확인할 조치 점검 |
| 작업실 | 유지 | 저장한 자료·메모와 실제 검토 과제 관리 |

근거: `web/static/index.html`의 8개 메뉴, `app.js`의 홈·다이제스트·분석·그래프 화면, `workspace.js`의 리뷰·이슈·작업실 구현을 확인했다.
홈과 이번 주는 주차 상태(`CUR_WEEK`)를 공유하고 주간 요약·주요 기사·급상승 내용을 반복한다. 리뷰에도 기간별 해설·주요 기사·과제 후보가 있다.
연관어는 키워드 간 관계를, 이슈 추적은 검색어가 등장한 기사의 시간순 목록을 보여준다. 분석 자체가 동일한 것은 아니지만, 주제를 찾고 근거 기사를 읽는 진입 과정이 겹친다.

## 1. 브리핑: 읽는 화면 하나

- 첫 화면은 이번 주. 상단에 주간 / 월간 전환과 기간 선택을 둔다.
- 구성 순서: 핵심 요약 → 주요 이슈와 근거 기사 → 이전 기간 대비 변화 → 검토할 과제 후보.
- 주간은 이번 주 변화와 바로 확인할 일, 월간은 여러 주에 걸친 흐름과 반복되는 주제에 집중한다.
- 요약과 본문은 하나의 리뷰 데이터를 사용한다. 별도의 홈 요약·다이제스트 해설을 중복 관리하지 않는다.
- 해설 안에서 인용한 기사는 하단 목록에서 반복 노출하지 않는다. 나머지 기사는 ‘관련 기사 더 보기’로 탐색에 연결한다.
- 상세 수치·일별 그래프·전체 출처는 펼쳐보기로 제공한다.
- 해설이 없는 기간에도 기간 집계와 주요 기사를 제공한다. 자동 작성된 해설처럼 표시하지 않는다.
- 과제는 후보 2~3개와 작업실 추가 버튼만 보여준다. 담당자·상태·이력 편집은 작업실에만 둔다.
- 홈의 급상승 상세와 관심 키워드 목록은 탐색으로 이동한다. 법령은 중요한 변경이 있을 때만 짧게 연결한다.
- 수집 현황은 메뉴 하단의 ‘수집 상태’ 접힘 영역으로 이동한다.
- 본문에서 중간 리뷰라는 설명을 반복하지 않는다. 기간·기준일·진행 상태는 짧은 메타데이터로 표시한다.

## 2. 탐색: 주제 하나, 보기 방식 여러 개

- 검색어와 기간을 한 번 선택하면 화면 전환에도 유지한다.
- 검색 전에는 급상승 주제와 관심 주제를 보여줘 출발점을 제공한다.
- 주제를 선택하면 기사 / 시간 흐름 / 연관어 세 가지 보기로 전환한다. 별도의 검색창이나 중복 결과 페이지를 만들지 않는다.
- ‘기사’는 근거를 읽는 기본 화면, ‘시간 흐름’은 보도 순서 확인, ‘연관어’는 다른 주제와의 연결 확인에 사용한다.
- 이슈 추적은 별도 메뉴 대신 ‘관심 주제로 등록’ 동작으로 바꾼다. 관심 주제에서 동일한 탐색 화면으로 돌아온다.
- 기존 분석의 ‘급상승’은 탐색 시작 화면, ‘기관’과 ‘교차’는 보조 탐색 옵션으로 옮긴다. 기존 6개 화면을 그대로 6개 하위 메뉴로 숨기는 방식은 피한다.
- 기존 연관어 점수와 기사 검색 방식을 유지한다. 시간순 기사 목록을 자동 사건 분석이나 의미 기반 추적으로 부르지 않는다.
- 현재 분석의 고정 기간과 이슈 추적의 기간 옵션이 다르므로, 통합 시 각 API의 기간 지원 범위를 먼저 맞춘다. 맞출 수 없는 지표는 실제 산출 기간을 별도로 표시한다.
- 공통 검색은 탐색 화면을 열고 검색어를 전달한다. 기사 상세와 스크랩 버튼은 모든 보기에서 동일하게 제공한다.
- 개인 관심 주제와 설정 파일의 알림 키워드는 저장 주체가 다르다. 화면에서는 구분해서 보여주며, 개인 등록이 서버 알림 설정을 바꾸지 않도록 한다.

## 3. 법령·규제와 작업실: 별도 목적 유지

법령·규제는 일반 기사 탐색과 달리 시행일·제도 변경·확인 조치가 중요하므로 독립 메뉴로 유지한다.
브리핑에는 요약 링크만 제공하고 상세 내용과 점검 항목은 이 화면에서만 관리한다.

작업실은 보관함·메모와 과제 검토를 유지한다. 브리핑은 후보를 발견하는 곳, 작업실은 선택한 과제를 관리하는 곳으로 구분한다.
HTML/Markdown 내보내기와 JSON 백업·복원도 작업실에 둔다.

## 구현 순서

1. 브리핑 통합: 주간 기본 화면, 월간 전환, 기간 선택, 중복 요약·기사 제거.
2. 탐색 통합: 검색어·기간 상태 통일, 기사·시간 흐름·연관어 전환, 개인 관심 주제 연결.
3. 내비게이션 정리: 4개 메뉴와 모바일 메뉴, 기존 주소 호환, 수집 상태 위치 조정.
4. 회귀 검증: 검색·리뷰·저장·추적·과제·내보내기·복원과 뒤로 가기 확인.

## 보존 및 완료 기준

- 기존 `#home`, `#digest`, `#reviews/...`는 해당 기간의 브리핑으로 연결한다.
- 기존 `#graph`, `#issues/...`, `#analysis/...`는 해당 탐색 보기로 연결하고 검색어를 보존한다.
- 전역 ‘지난 회차’ 선택을 브리핑 내부로 이동한다. 탐색 기간이나 법령 화면을 암묵적으로 바꾸지 않는다.
- 브리핑에서 탐색으로 이동할 때 관련 주제와 기간을 전달한다. 뒤로 가면 원래 기간과 보기로 복귀한다.
- 개인 저장소 키·스크랩·메모·관심 주제·과제 이력과 기존 백업 파일의 호환성을 유지한다. 저장된 리뷰 사본을 임의로 덮어쓰지 않는다.
- 직접 작성한 리뷰 파일과 무 API 리뷰 운영을 유지한다. 메뉴 통합을 이유로 추가 모델 호출을 넣지 않는다.
- 새 최상위 메뉴는 데스크톱·모바일 모두 4개이며, 동일 기간의 전체 요약이나 동일한 과제 편집 기능이 여러 화면에 반복되지 않는다.
- 연관어·시간 흐름 전환 시 검색어를 다시 입력할 필요가 없고, 모든 보기에서 근거 기사 상세와 스크랩에 접근할 수 있다.
- 로딩·빈 결과·오류·키보드 탐색·모바일 레이아웃과 기존 링크를 검증한다.
