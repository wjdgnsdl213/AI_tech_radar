# SAB Trend 대시보드 디자인 개편 계획

작성일: 2026-09-12. 상태: 제안. 이번 작업의 산출물은 개편 계획이며 서비스 UI 구현·배포는 포함하지 않는다.

## 1. 목표와 방향

핵심 흐름을 ‘주간·월간 변화 읽기 → 기사와 근거 확인 → 저장·메모 → 과제 검토’로 정리한다. 밝은 중립색 배경, 명확한 글자 위계, 정돈된 목록을 사용하는 읽기 중심의 업무 대시보드를 권장한다.

- 메뉴 아래 회색 설명은 두지 않는다.
- 사용법은 필요한 컨트롤 옆 도움말에 담고, 마우스·키보드·터치로 확인할 수 있게 한다.
- 발행일·시행일·출처·선택 기간처럼 판단에 필요한 정보는 읽을 수 있는 크기로 표시한다.
- 주간·월간 흐름과 보고서는 개조식으로 작성하고 핵심 단어·수치만 굵게 표시한다.
- 화면 이동과 검색 조건을 예측 가능하게 유지하고 재방문 응답성을 지킨다.

## 2. 현재 화면에서 확인한 내용

배포 사이트 https://sabtrend.up.railway.app/ 의 열린 Chrome 탭에서 아래 순서로 이동하며 화면과 DOM을 확인했다. 화면 캡처는 이번 대화에 표시했다. 소스는 web/static/index.html, style.css, workspace.css를 함께 확인했다.

| 순서 / 화면 | 현재 상태 | 개편 방향 | 이유 |
| --- | --- | --- | --- |
| 1. 주간 브리핑 | 개조식·근거 링크는 갖춰져 있으나 넓은 읽기 영역과 반복 날짜 정보가 있음 | 본문 폭 제한, 기간 조작 한 줄, 날짜 메타 정리 | 내용의 우선순위와 읽는 위치를 명확히 함 |
| 2. 탐색 진입 | 급상승·관심 주제·설정 알림 카드가 앞에 나오고 기사 목록은 별도 진입 | 초기 화면을 기사 목록으로 변경, 관심 주제와 급상승은 보조 영역 | 기사 탐색이라는 목적에 바로 도달 |
| 3. 법령·규제 | 목록은 간결하지만 제목·태그·날짜 중심 | 핵심 변경 요약과 시행일을 목록에서 강조 | 상세를 열기 전 관련성을 판단 |
| 4. 작업실 빈 상태 | 자료가 없어도 선택·백업·보고자료 만들기 컨트롤이 넓게 노출됨 | 빈 상태에 자료 찾기 안내 행동, 선택 후 보고자료 도구 노출 | 현재 할 수 있는 행동에 집중 |

모바일 실기기, 확대 배율별 레이아웃, 스크린리더, 색 대비 수치, 첫 진입 성능은 이번 계획 단계에서 측정하지 않았다. 월간 보고서 출력과 기사 상세·과제 편집은 구현 단계의 검증 대상이다. 화면 캡처만으로 접근성 준수를 판정하지 않는다.

## 3. 메뉴와 정보 구조

| 주 메뉴 | 페이지 안의 보기 | 역할 |
| --- | --- | --- |
| 브리핑 | 주간 / 월간 | 선정된 흐름과 의미 읽기, 기간별 보고서 확인 |
| 기사 탐색 | 기사 목록 / 시간 흐름 / 연관어 | 같은 검색 조건으로 근거 자료 조사 |
| 법령·규제 | 목록 안의 기간·기관·시행 상태 필터 | 제·개정 내용과 시행 일정 확인 |
| 보관함 | 저장 자료 / 과제 검토 | 스크랩·메모·보고자료·검토 상태 관리 |

사이드바에는 위 네 메뉴만 둔다. 하위 보기는 각 페이지 상단의 가로 탭으로 제공하며, 사이드바의 펼침식 소메뉴와 중복하지 않는다. 수집 상태는 사이드바 하단에 둔다.

- 홈·이번 주·리뷰는 브리핑 진입점 하나로 통합 유지한다.
- 연관어와 시간 흐름은 같은 주제를 보는 방식이다. 검색어·기간·주제 필터를 공유하고 보기 전환에도 유지한다.
- 관심 주제의 등록·해제는 기사 탐색에서 통합한다. 기존 서버 알림 키워드는 관리 성격으로 분리해 보조 메뉴에 배치하고 개인 관심 주제와 같은 기능처럼 노출하지 않는다.
- 기관·교차 분석은 ‘분석 도구’ 보조 메뉴로 이동한다. 기사 검색과 적용 기간이 다르면 별도 기간을 명확히 보여준다.
- 과제는 브리핑에서 후보로 소개하고, 실제 상태 변경·메모는 보관함에서 수행한다.
- 기간별 월간보고서 내려받기는 월간 브리핑, 사용자가 선택한 자료의 내보내기는 보관함에 둔다.

## 4. 화면 공통 규칙

- 데스크톱 사이드바는 216~232px, 본문 최대 폭은 1,280px를 시작값으로 한다.
- 페이지 제목·현재 상태·주요 행동을 첫 줄에 배치하고 검색/필터는 바로 아래에 둔다.
- 페이지 내 검색 입력은 한 곳만 둔다. 기사 탐색은 기사, 법령은 법령, 보관함은 저장 자료를 검색하며 검색 대상이 레이블에 드러나게 한다. 브리핑에서는 ‘기사 찾기’로 기사 탐색에 연결한다.
- 검색 조건은 제출 시 URL에 반영한다. 뒤로 가기와 새로고침에서 기간·검색어·정렬이 복원되어야 한다.
- 배경 후보 #F7F8FA, 콘텐츠 #FFFFFF, 본문 #20242C, 보조 정보 #5B6472, 강조 #315BE8. 실제 사용 조합은 대비 측정 후 확정한다.
- 카드 모서리는 8~12px, 경계선은 얇게, 그림자는 떠 있는 메뉴·상세 패널에 제한한다.
- 간격은 4/8/12/16/24/32px 기준으로 통일한다. 카드 안에 카드를 반복해서 넣기보다 제목·여백·구분선으로 영역을 나눈다.
- 아이콘은 동일한 선형 라이브러리로 통일하고 핵심 행동에 이름을 함께 표시한다. 파란색은 선택 상태·주요 행동에 집중한다.

## 5. 글꼴과 가독성

첫 추천은 Pretendard Variable이다. 현재 코드에도 지정돼 있으며 한글·영문·숫자가 섞이는 이 제품에 적합하다는 디자인 판단이다. 종류 교체보다 굵기·행간·읽기 폭의 정리가 우선이다. 비교 시안용 대안은 UI 본문용으로 제작된 SUIT Variable로 한다. 한 화면에서 두 한글 폰트를 혼용하지 않는다.

| 용도 | 크기 시작값 | 굵기 | 기타 |
| --- | --- | --- | --- |
| 페이지 제목 | 28px | 700 | 행간 1.3 |
| 섹션 제목 | 20px | 650~700 | 행간 1.45 |
| 기사 제목 | 17px | 600 | 목록 기본 최대 두 줄 |
| 본문·AI 요약 | 16px | 400~450 | 행간 1.7~1.8 |
| 메뉴·버튼 | 15px | 500~600 | 주요 터치 대상 높이 44px |
| 출처·날짜 | 14px | 400~500 | 과도하게 흐리게 표시하지 않음 |

- 긴 리뷰의 실제 문장 영역은 720~800px 정도에서 시작해 한글 줄 길이를 확인한다.
- 문장 전체를 굵게 하지 않고 핵심 키워드·변화량·기한만 강조한다.
- 숫자 표는 자릿수 폭을 맞추고 정렬을 통일한다.
- 글꼴은 WOFF2 서브셋·font-display 설정을 점검한다. 자체 호스팅과 현재 CDN 방식은 실제 로딩을 비교해 결정하며 전체 한글 폰트를 무조건 선로딩하지 않는다.

공식 자료:
- Pretendard: https://github.com/orioncactus/pretendard
- SUIT: https://github.com/sun-typeface/SUIT/blob/main/.github/README.md

## 6. 페이지별 변경

### 브리핑

상단은 페이지 제목, 주간/월간, 기간 이동, 저장·내보내기로 정리한다. 첫 콘텐츠는 핵심 변화 세 가지, 아래는 이슈별 상세 분석으로 구성한다. 넓은 화면에서만 짧은 목차를 오른쪽에 두고 좁아지면 본문 위에 접어 둔다.

이슈 하나는 ‘짧은 제목 → 변화·사례 2~4개 항목 → 근거 기사’ 순서다. 근거는 제목·출처·날짜와 저장 버튼을 독립 열로 배치하고 긴 제목이 버튼을 밀어내지 않게 한다. 기본 두 건을 보여주고 나머지는 ‘근거 N건 더 보기’로 펼친다. 상세에서 전체 제목과 모든 근거를 확인할 수 있게 한다.

기간은 제목 옆에 한 번 표시한다. 작성 기준일은 간단히 드러내고 수집·갱신 상세 시각은 도움말에 둔다. 해설 기준일과 실시간 기사 집계가 다를 경우 혼동되지 않도록 한다. 주요 변화 없이 수집량만 큰 지표 카드를 상단에 늘리지 않는다.

월간 브리핑과 출력 보고서는 제목·소제목·개조식·수치 강조 규칙을 공유한다. 화면에서 접힌 근거는 출력에서 모두 펼치고 긴 URL과 기사 영역의 페이지 넘김을 점검한다.

### 기사 탐색

진입 즉시 최근 7일 기사 목록을 보여준다. 기본 정렬은 최신순, 필요하면 관련도순으로 바꿀 수 있게 한다. 기존 교차 점수는 관련도 정렬에 활용한다.

상단에 검색어·기간·주제·정렬을 묶는다. 급상승 주제와 관심 주제는 짧은 추천/필터 영역으로 배치한다. 기사 제목 1~2줄, 저장된 AI 요약 최대 두 항목, 출처·날짜, 저장 동작으로 목록 행을 구성한다. 전체 요약은 상세에서 확인한다.

상세는 데스크톱 오른쪽 패널, 모바일 전체 화면으로 제공하는 안을 권장한다. 닫으면 검색 결과와 스크롤 위치로 돌아간다. 원문 이동은 별도 링크다.

시간 흐름은 ‘최신순 / 오래된순’을 유지한다. 연관어는 관련 단어 목록을 기본으로 하고 그래프는 선택해서 펼치는 방식으로 복잡도를 낮춘다. 그래프 라이브러리·데이터는 선택 시 불러온다.

### 법령·규제

법령명 아래 핵심 변경 요약을 1~2개 항목으로 표시한다. 시행일과 ‘시행 예정/시행 중’ 상태를 눈에 띄게 정리하고 기관·법령 종류는 보조 정보로 배치한다. 상태는 명시적 시행일로만 판정하며 일자가 없으면 확인 필요로 표시한다.

상세에서 제·개정 이유, 확인 가능한 적용 대상, 전체 요약, 공식 원문을 제공한다. 날짜를 감추는 도움말은 사용하지 않는다. 기본 정렬은 최근 발령일, 선택 정렬은 시행일로 제안한다.

### 보관함

저장 자료와 과제 검토를 상단 탭으로 나눈다. 저장 자료는 자료 유형·주제 필터, 메모·태그 편집, 다중 선택을 제공한다. 자료를 선택했을 때 하단 행동 영역에 ‘보고자료 만들기’를 표시한다.

빈 상태에는 ‘기사 찾기’와 ‘메모 작성’만 우선 제공한다. 전체 백업·복원은 더보기로 이동한다. 브라우저 저장이라는 실제 저장 범위는 도움말에서 명확히 알리고 기존 저장 자료와 개인 메모를 유지한다. 기기 간 동기화는 별도 기능 범위다.

과제 검토는 제목·상태·근거·최근 메모가 보이는 목록을 기본으로 하고 상태 필터를 둔다. 실제 기존 상태값을 점검한 뒤 이름과 표시 순서를 정하며 데이터 상태를 임의 변경하지 않는다.

## 7. 모바일·접근성·응답성

- 390 / 768 / 1,280 / 1,920px에서 확인한다. 좁은 화면은 접이식 사이드바와 한 열 목록을 사용한다.
- 200% 확대에서도 핵심 정보·버튼이 겹치지 않고, 긴 근거 제목·한국어 줄바꿈 때문에 가로 스크롤이 생기지 않아야 한다.
- 도움말은 hover 외에 focus·터치로 열고 Escape로 닫을 수 있어야 한다. 필수 입력 이름·오류 메시지는 도움말 안에 숨기지 않는다.
- 일반 텍스트 대비 4.5:1, 큰 텍스트 3:1을 목표로 측정하고 선택 상태를 색만으로 표현하지 않는다.
- 상세 패널을 닫으면 원래 항목으로 키보드 포커스를 돌려준다. 스크린리더 레이블·탭 상태를 점검한다.
- 목록 전환은 즉시 반응하고 팝오버·상세 패널에만 짧은 전환을 적용한다. 모션 축소 설정을 지원한다.
- 기존 요청 캐시·중복 요청 제거·검색 인덱스를 보존하고 화면에 필요한 데이터만 요청한다.
- 캐시가 있는 재방문은 즉시 기존 내용을 표시하고, 첫 진입은 레이아웃 자리표시자를 보여준다. 로딩·빈 결과·요약 미작성·실패를 구분한다.
- 동일 기기·동일 질의·동일 캐시 조건으로 변경 전후 p50/p95를 비교한다. 애니메이션으로 느린 서버 응답을 해결했다고 간주하지 않는다.

## 8. 구현 순서와 완료 기준

1. **대표 화면 시안**: 브리핑·기사 탐색을 데스크톱/모바일로 제시하고 실제 한글 제목·요약으로 읽기 폭과 Pretendard/SUIT를 비교한다. 산출물은 비교 가능한 화면 시안이다.
2. **공통 구조**: 네 메뉴 이름·가로 탭·검색 위치·색·서체·간격·기본 컨트롤을 적용한다. 기존 링크가 새 화면으로 연결되는지 확인한다.
3. **핵심 읽기 흐름**: 브리핑·기사 목록·기사 상세·시간 흐름·연관어 순서로 적용한다. 검색 조건 보존과 근거 넘침 방지가 완료 기준이다.
4. **법령·보관함·보고서**: 변경 요약·시행일, 저장·메모·과제, 인쇄 결과를 통일한다. 기존 스크랩·메모·백업을 실제 샘플로 검증한다.
5. **통합 검증과 배포 준비**: 반응형·키보드·긴 텍스트·빈 상태·오류·성능을 점검한다. 테스트와 화면 비교가 통과한 코드만 커밋·배포 대상으로 삼는다.

주요 확인 시나리오:
- 첫 화면에서 이번 주 핵심 흐름을 읽고 근거 기사를 열 수 있다.
- 키워드 검색 후 시간 흐름·연관어로 전환해도 조건이 유지된다.
- 기사 상세를 닫거나 뒤로 가도 목록 위치와 조건이 유지된다.
- 법령 목록에서 무엇이 바뀌었고 언제 시행되는지 확인할 수 있다.
- 저장한 기사에 메모를 붙이고 선택 자료만 보고자료로 내보낼 수 있다.
- 모든 핵심 기능을 모바일·키보드에서 사용할 수 있다.

우선 범위에서 제외: 새 홈 페이지, 별도 이슈 추적 메뉴, 로그인·기기 간 동기화, AI 요약 대량 생성, DB 교체. 별도 기능 확장 없이 기존 제품의 읽기·탐색·정리를 개선하는 계획이다.

기존 작업 상태: src/insight.py 및 tests/test_reviews.py에 이전 수동 요약 보호 작업의 미완료 변경이 있다. 디자인 변경과 별도 작업으로 취급하고 기존 변경을 덮어쓰지 않는다.
