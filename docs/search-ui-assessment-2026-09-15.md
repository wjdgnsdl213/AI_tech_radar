# 브리핑·탐색 수정 및 검색 평가

2026-09-15. 현재 `web/static` 화면 기준. 로컬 수정이며 배포는 포함하지 않는다.

## 적용 내용

- 브리핑의 기간 레이블과 선택창을 한 줄로 정렬.
- 저장된 2026-W37 리뷰의 ‘지난주’를 ‘지난 주’로 수정. CLI의 ‘이번주’도 ‘이번 주’로 통일. 다른 UI 코드의 해당 표기는 이미 띄어쓰기가 되어 있었다.
- 비교 상세 수치와 일별 기사 수를 주요 기사 뒤, 브리핑 맨 아래의 독립적인 두 토글로 배치. 두 토글은 기본적으로 접힌 상태.
- 상세 통계 최대 폭 760px, 숫자 우측 정렬, 표 머리글·행 구분과 숫자 고정 자릿수 폭 적용. 좁은 화면에서는 표 영역만 가로 스크롤.
- 일별 차트는 날짜 / 가로 막대 / 기사 수의 대응 목록. 막대만 있는 그림과 긴 숫자 나열을 제거. 0건은 길이 0으로 표현.
- 탐색 검색창과 기간 프리셋 사이 18px. 검색어 제목 아래에 기사·시간 흐름·연관어 탭 배치.
- 연관어 중심어 기사는 기사 탭과 동일한 `/api/search` 조건·첫 페이지 크기를 사용. 연관망 생성 여부와 독립적으로 기사 조회. 노드 클릭 시 이웃 키워드 조회는 기존 색인 기반을 유지하고 집계 범위를 표시.
- 탐색 탭에 보조 탐색용 클릭 핸들러까지 붙던 선택자 범위를 제한하여 불필요한 중간 화면 전환 방지.

## 연관어 불일치 원인과 수정 범위

기사 검색은 `items.title` 또는 `items.summary` 부분 문자열 검색, 기존 연관어 기사는 `kw_item.keyword` 정확 일치였다. 날짜 조건 자체는 두 경로 모두 한국 시간의 시작일부터 종료일 전체까지 적용한다. 키워드 색인에 없는 표기, 구문 또는 색인에 포함되지 않은 기사는 제목 검색에서 발견되어도 키워드 조회에서 빠진다.

실제 DB, 2026-09-01~07, 전체 주제:

| 검색어 | 선별 기사 검색 | 기존 키워드 기사 조회 |
| --- | ---: | ---: |
| AI | 5,907 | 0 |
| SKT | 62 | 17 |
| 소상공인 | 758 | 0 |

키워드 색인의 갱신 범위·추출 기준까지 이번에 변경하지 않았다. 연관망은 여전히 전체 코퍼스의 사전 계산 결과다. 선택 기간에 한정한 연관망이 필요하면 날짜별 동시 출현 집계가 별도 과제이며, 현재 설명에 이 구분을 명시했다. 중심어의 기사는 검색 탭과 같고, 다른 노드를 고르면 해당 키워드로 대상을 바꾸는 동작이다.

## 상단 검색 범위에 대한 판단

**페이지별 검색을 기본으로 권장한다.** 같은 위치의 입력창이 항상 탐색으로 이동하면 현재 페이지의 맥락이 끊기며, 법령 화면에는 이미 별도 검색 기능이 있어 중복된다. 이번 요청은 평가이므로 상단 검색의 동작은 변경하지 않았다.

| 페이지 | 권장 검색 대상·이름 | 결과 위치 |
| --- | --- | --- |
| 탐색 | ‘기사 검색’ — 제목·요약, 현재 기간·주제 적용 | 탐색의 기사·시간 흐름·연관어 보기 |
| 법령·규제 | ‘법령·규제 검색’ — 법령명·변경 요약 | 법령 목록; 페이지 이동 없이 필터 유지 |
| 작업실 | ‘저장 자료 검색’ — 스크랩·메모·제목 | 보관함 목록 |
| 브리핑 | 단기: ‘현재 브리핑에서 찾기’ — 선택 기간의 해설·근거 | 해당 문단 강조 및 일치 수; 검색어를 지우면 전체 복구 |
| 브리핑 확장 | ‘브리핑 전체 기간 검색’ — 주간·월간 아카이브 | 기간·제목·해당 문장을 포함한 브리핑 결과 목록 |

브리핑 검색에 기사 DB 검색을 그대로 연결하면 ‘브리핑 검색’이라고 불러도 실제로는 기사 검색이므로 대상이 어긋난다. 선택 기간 안의 찾기는 브라우저에서 처리할 수 있고, 전체 아카이브 검색은 편집 해설을 포함하는 별도 색인/API가 필요하다.

통합 검색이 꼭 필요하면 별도 ‘전체에서 찾기’ 진입점을 둔다. 기사 / 브리핑 / 법령 / 내 저장 자료별 그룹과 검색 범위를 표시하고, 브라우저에만 있는 개인 저장 자료는 클라이언트에서 검색한다. 현재 탐색은 기사 검색에 일부 법령 결과를 덧붙인 형태여서 이름만 ‘통합 검색’으로 바꾸는 것으로 완성되지 않는다.

권장 순서: 페이지별 검색으로 일관성 확보 → 실제 교차 검색 수요 확인 → 별도 통합 검색. 검색 조건은 URL 또는 페이지 상태에 보존해 뒤로 가기로 복원한다.

## 검색 속도 측정

측정 스크립트: `python -m scripts.profile_search`, `python -m scripts.profile_explore`.
Windows 로컬 Python 프로세스에서 현재 원격 PostgreSQL 조회. 2026-09-01~07, 기사 탭과 동일한 관련도 정렬, 25개. 각 검색어의 첫 호출 1회와 즉시 반복 1회이며 p50/p95 또는 배포 환경 측정이 아니다.

| 검색어 | 첫 API 함수 호출 | SQL 목록 / 건수 / 주제 조회 | 즉시 반복 함수 호출 |
| --- | ---: | --- | ---: |
| AI | 0.732초 | 0.226 / 0.172 / 0.028초 | 0.00003초 |
| SKT | 0.226초 | 0.174 / 0.011 / 0.021초 | 0.00002초 |
| 소상공인 | 0.091초 | 0.044 / 0.016 / 0.012초 | 0.00003초 |

별도 전체 기간 SKT 최신순 첫 호출은 0.730초였다. `EXPLAIN`에서 기존 제목·요약의 부분 GIN trigram 인덱스 사용을 확인했다. 추가 법령 조회 AI 3건 요청은 0.062초였다. 반복 호출 값은 **서버 메모리 캐시의 함수 반환 시간**으로, 브라우저 왕복 시간을 뜻하지 않는다.

### 확인한 지연 요소

1. 검색은 목록, 전체 건수, 주제 태그의 세 SQL을 순차 실행한다. 첫 요청에는 연결 설정·풀 확보 시간도 포함된다. 목록이 준비돼도 건수·태그 완료 후 반환한다.
2. `AI` 같은 짧은 부분 문자열 검색은 현재 trigram 색인의 장점이 제한된다. 추출 가능한 trigram이 없는 LIKE 패턴은 인덱스 전체 스캔으로 퇴화할 수 있다. [PostgreSQL 공식 설명](https://www.postgresql.org/docs/17/pgtrgm.html). 이번 수치에서 AI의 전체 건수 조회도 다른 검색어보다 길었다. 단, 이번 측정은 AI의 실행계획 자체를 확인한 결과는 아니다.
3. 브라우저와 서버의 검색 캐시는 모두 30초. 키워드·날짜·정렬·페이지가 바뀌거나 TTL이 지나면 다시 조회한다. 서버 캐시는 프로세스별이므로 재시작·여러 워커에도 영향을 받는다.
4. 기사 탭은 법령도 별도 조회한다. 기사와 병렬이라 항상 직접 지연을 더하는 것은 아니지만, 동시 부하와 전체 화면 완료 시점에 영향을 줄 수 있다.
5. 기존 연관어 화면은 연관망 조회 및 빈 색인 확인 후에 기사 목록을 요청했다. 이번 수정은 기사 요청을 독립적으로 시작하며, 기사 탭에서 바로 전환하면 동일 요청의 브라우저 캐시도 재사용한다.

### 권장 개선 순서

1. 배포 환경의 실제 느린 검색어에서 요청 시작·첫 바이트·응답 완료·목록 렌더와 SQL 시간을 함께 기록. 첫 방문/반복 방문, 1~2자/3자 이상, 전체/날짜 범위를 나누어 최소 30회 p50/p95 비교. 브라우저·서버·DB 중 병목을 먼저 확정.
2. 페이지 간 동일 검색 요청 재사용은 이번 중심어 수정에 적용. 다음으로 검색 총건수 캐시를 페이지·정렬과 분리해 재사용한다. 목록을 먼저 보여주고 총건수는 후속 응답으로 갱신하는 방식도 비교하되 CSV/페이지 수 일관성을 검증한다.
3. 페이지별 검색을 적용하면서 다른 유형의 자동 조회를 제거하거나 ‘법령에서도 찾기’ 선택 시 실행한다. 급상승 보조 목록은 본 검색과 별도 캐시·로딩 상태로 운영한다.
4. 수집 배치의 갱신 주기에 맞는 캐시 무효화 키를 도입해 30초보다 오래 재사용할 수 있는 결과를 구분. 날짜가 지난 자료라도 백필·수정이 있으므로 무기한 캐시는 금지한다.
5. 짧은 단어 성능이 실제 병목이면 1~2자용 n-gram/토큰 색인을 별도 검토. `AI` 검색을 ‘인공지능’으로 몰래 치환하거나 단어 검색으로 바꾸지 않는다. 기존 부분 문자열·대소문자·날짜·선별 기준과 결과 동등성을 먼저 정의한다.
6. DB와 앱의 배포 지역, 연결 풀 대기 시간을 확인한다. 이미 작동하는 trigram 인덱스를 다시 만드는 작업은 우선순위가 아니다.

## 검증

- JavaScript 테스트 27개 통과(중심어/이웃 노드의 요청 조건 회귀 포함).
- 탐색 API·응답 캐시 Python 테스트 11개 통과. 기존 FastAPI startup API 사용 중단 예정 경고 4개.
- 브라우저에서 AI, 9월 1~7일 기사 탭 5,907건 → 연관어 5,907건 및 25개 기사 표시 확인. 연관망이 없는 경우에도 목록 유지.
- 브리핑 하단 두 토글 동시 열림, 압축된 표와 날짜·가로 막대·숫자 차트를 실제 데이터로 확인.
- 모바일 390px에서 탐색·브리핑 페이지 가로 넘침 없음, 기간 선택 한 줄 정렬 및 두 토글 동시 열림 확인. 표만 자체 가로 스크롤.
- 배포 사이트의 사용자 체감 속도 개선 수치는 아직 측정하지 않았으므로 성능 개선율을 주장하지 않는다.
