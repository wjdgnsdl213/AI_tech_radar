성과 정리 (자소서용)
============================================================
※ 1·2·4번은 작성자가 적은 메모를 형식만 맞춰 정리한 것이다. 사실은 그대로 두었다.
   3번만 실제 코드·DB에서 수치를 확인해 채웠다.


────────────────────────────────────────────────────────────
1. '소상공인 365' — 내 가게 경영진단 개선
────────────────────────────────────────────────────────────
문제  외부 업체가 생성형 AI로 만든 경영진단 요약이 수치 나열이라 읽기 어려웠다.
      정보가 팝업 안에 스크롤로만 쌓여 있어 어디에 무엇이 있는지 알 수 없었다.

한 일  · 요약 로직을 룰베이스로 단순화 — 소상공인이 바로 읽을 수 있는 형태로
       · 가명데이터 50개를 통계 기반 합성으로 500개까지 늘려 검증
       · 경영진단 화면 시안 4종 제작 (탭형 / 대시보드형 / LOC형 / 아코디언형)

성과  · 데이터 기간이 6개월이라 계절성을 못 담는 문제를 발견해 1년 이상으로
        늘릴 것을 제안 → 팀의 AI비즈파트너 목업에 반영, 계절성 피드백 제공
        (예: 여름철 국밥집 매출 하락 → 냉면 개시 추천)
      · UI 시안 중 탭형이 AI비즈파트너 목업에 반영


────────────────────────────────────────────────────────────
2. 소상공인 트렌드 레이더
────────────────────────────────────────────────────────────
문제  '두바이 쫀득 쿠키'처럼 유행을 타는 것이 소상공인 매출에 직결되는데,
      개별 점포가 유행을 제때 알아채기 어렵다.

한 일  · 소스 2종 확보
         - 공단 조간스크랩 8개월치를 수집·분석해, 그 내용 기반으로 뉴스 수집
           (정책·경제 트렌드)
         - 네이버 API로 뉴스·블로그 수집 (소비·유행 트렌드)
       · 정책/경제·사업 급상승 키워드 순위
       · 소비/유행 급상승 키워드 순위
       · 키워드 연관 네트워크 (검색 → 연관어 추출 → 원문 URL 제공)
       · 지역 × 음식 키워드 순위·추이
       · 키워드별 언급 빈도 및 급상승 스코어 추이

3. AI·빅데이터 트렌드 레이더 (SAB Trend)
────────────────────────────────────────────────────────────
문제  팀이 따라가야 할 주제가 AI·빅데이터·소상공인 셋인데 이를 한꺼번에 다루는
      매체가 없다. 국내 뉴스·해외 기술 커뮤니티·법제처를 각각 봐야 해서 아무도
      다 못 본다. 정보가 없어서가 아니라 너무 많아서 못 읽는 문제였다.
      → 목표를 '많이 모으기'가 아니라 '읽을 만한 것만 남기기'로 잡았다.

한 일  · 수집  5개 소스 매일 자동 수집 (누적 90,996건)
               네이버뉴스 API · Hacker News · GeekNews · 법제처 API
       · 선별  세 축 태깅 → 교차 점수 → 신디케이션(받아쓰기) 중복 제거
       · 해설  게시물 AI 요약 / 주간 흐름 / 월간 리뷰 / 주간 과제 후보
               법령·규제 변경사항 요약 + 팀 확인사항
               기관들의 움직임 종합 (40곳을 한 편으로 묶어 제시)
       · 화면  급상승 키워드(축별) · 연관어 네트워크 · 교차 기사 · 기관 동향
               관심 키워드 알림 · 월 단위 조회 · 통합 검색
       · 배포  Docker → Railway 상시 서비스, Supabase Postgres, 일일 자동 실행

성과  · 필터를 사람 라벨 50건으로 실측해 교체
        임베딩 필터 precision 0.560 / recall 0.519
        → 축 기준 필터 precision 0.605 / recall 0.963 (정확도 유지, 재현율 2배)
      · 받아쓰기 기사 35% 제거 (50,956건 → 33,094건)
      · 응답 속도 개선 — 연관어 4.6초 → 0.16초, 급상승 11.2초 → 1.3초
      · 로컬 310MB 인덱스를 압축 표 4종으로 재설계해 원격 DB로 이관
        → 코드만 받으면 어느 PC에서도 전 기능 동작

규모  Python·JS 약 8,900줄 / 커밋 91개 / 2026-08 ~ 진행 중
스택  FastAPI · SQLAlchemy · PostgreSQL(Supabase) · sentence-transformers
      · kiwipiepy · Claude API · Docker · Railway

4. 국캐치 — 국회 상임위 모니터링 자동화
────────────────────────────────────────────────────────────
문제  상임위 회의 날마다 공단·팀 관련 발언을 모니터링해 정리하는 업무가 있다.
      대부분 이어폰을 꽂고 다른 일과 병행하거나, AI 자막을 보며 직접 타이핑한다.
      이 작업만 자동화해도 팀별 최소 1~2명 × 6시간 이상을 아낄 수 있다고 봤다.

한 일  · 팀별 키워드와 회의 주소를 입력하면 AI 자막을 자동 저장
       · 키워드에 걸리는 발언이 나오면 알림 + 해당 구간 저장
       · 생성형 AI로 보고서 초안까지 자동 작성

면접에서 깊이 이야기할 거리
────────────────────────────────────────────────────────────
· (3번) 공들여 만든 임베딩 필터를 측정 결과로 껐다. 시드가 문제인 줄 알고
  사람 라벨로 시드를 다시 만들어 2겹 교차검증까지 했지만 AUC가 같았다.
  사람이 가른 경계가 '주제'가 아니라 '성격'이라 문장 임베딩이 담지 못했다.
  다만 같이 껐던 중복 제거는 되살렸다 — 한 덩어리로 보이던 기능을 쪼개
  쓸모 있는 절반만 남겼다.
· (1번) 요약 품질을 보다가 데이터 기간이라는 근본 원인을 찾아 제안했고,
  그 제안이 실제 제품 목업에 반영됐다.
· (3번) 목표(필터 precision 85%)에 미달했다는 점과, 정확도만 올리려다
  관련 있는 것의 절반을 버리고 있었다는 것을 측정으로 알게 된 과정.
